## Live page (built 2026-10-21)
- **One page** (`live.js`, `window.B5Live`; nav "Live" after My Team), top to bottom: week links, the NFL games strip, all 6 matchup cards, then the **selected matchup** directly below the cards (`#lvDetail`). Clicking a card selects it in place (no page change, no hashchange): the card is highlighted (`.sel`, `aria-current`), the detail loads below (only that matchup's roster, scores and plays are fetched), the URL becomes its deep link via `history.replaceState`, and on phones (≤760 px) the page scrolls smoothly to the detail, just under the sticky header. Default selection: the deep-linked team's matchup, else the signed-in manager's own matchup, else the first card (cards are ordered by away team). The shell (title, label, week links) is built once per week; the strip, cards and detail are re-filled in place, so Realtime updates never reload the page or the selected matchup and keep open breakdowns.
- **Routes** (`route.js`): `#live` (current week), `#live/<week>`, **`#live/<week>/<franchiseId>`** (that team's matchup selected, either side). The separate matchup detail page is gone: old `#live/<week>/<away>-<home>` and `#matchup/<week>/<away>-<home>` links return `redirect` and app.js rewrites the hash in place (`history.replaceState`). Schedule cards link `#live/<week>/<away>`, My Team `#live/<week>/<own team>`. Week links are `<a href="#live/<w>">`, so they never leave the page (the Schedule bug can't recur). `B5Live.stop()` runs on every route change (closes the socket and timers).
- **Scoreboard:** one card per matchup (both teams, logos, `matchups` totals, leader marked, "X done · Y playing · Z to go · N bye" per team, and "⚠ N starters on bye" when any) with status **Upcoming / Live / Final (unofficial) / Final (official)**. Official = the week's `score_weeks.status` is `pending_review` or `final` (nflverse has it); otherwise from the starters: **Live only when at least one starter's NFL game is in progress or finished this week**; none started = Upcoming, none playing or to go = Final (unofficial). **A bye is its own status** (bug fixed 2026-10-21: byes counted as "done" made matchups Live before any game started): never done, playing or to go, and never starts a matchup. A hidden starter is to go, or bye when his slot is flagged `bye`. A team with no game this week is only a bye once the week's games are loaded. Strip of the week's NFL games (score, `status_detail` clock, kickoff time; dark thin scrollbar, like the week links).
- **Matchup detail:** both lineups side by side in slot order (QB RB RB WR WR WR TE K DEF), then the bench (badge "BN", position on the player line; points shown, **never counted**). Each player: NFL team, opponent (`vs`/`@`), game status (clock, kickoff time, Final, Bye) and points; **a player on bye shows a BYE tag instead of 0.0** (red for a starter, whose name is red too; grey on the bench). Bye starters are counted in the team header's "⚠ N starters on bye". Tap a player for the breakdown: `player_scores.lines` (`{stat, value, points, text}`, e.g. "52-yd receiving TD (51–75) → 10", "112 total yards (100+): 6 → 6", "47-yd field goal (31–59): 3.1 + 0.1 × 16 (per yard over 31) → 4.7"). Scoring-play feed from `score_events` (the two teams' starters, newest first, game clock + time, changed lines); **6+ points on one play = "Big play"**. The detail section is max 820 px wide on desktop; everything works at 390 px.
- **Same engine, no second calculation:** `src/scoring/explain.ts` `breakdown(position, stats, points?)` = `scoreStatLine(...).lines` plus a description of the rule that produced each line; a commissioner-pinned score adds an "override" line so the lines always add up. Written by the live scorer (source live) and `scripts/shadow.mts` (final). The page only displays them. Tests: `explain.test.ts` (examples, real games vs MFL totals, 3,000 random stat lines sum to the engine's total, every rule described).
- **Scoring plays:** trigger `private.log_score_event` on `player_scores`: every **live** change in a player's points inserts a `score_events` row (delta, new points, per-stat changed lines with "Taken away: ..." for corrections, the game's period/clock/`status_detail` from `nfl_games`). Unchanged passes and final (nflverse) rewrites log nothing. The live scorer writes `nfl_games` (score, `period`, `clock`, `status_detail`, `updated_at`) **before** `player_scores`, so plays carry the clock. Public read, nobody writes but the trigger and server jobs.
- **Public read, lineups revealed at kickoff:** `public.live_lineups(season, week)` (security definer, anon + authenticated): each starter from his game's kickoff on; before that his slot comes back with `player_id` null (shown "🔒 Revealed at kickoff"), except to that team's managers and the commissioner (full lineup). Same rule as the members' `lineup_slots` policy, extended to visitors; `lineup_slots` itself stays members-only. While a team has hidden starters, bench players whose game hasn't started aren't listed (one could be the hidden starter). Bench = current `roster_entries` minus starters (for past weeks that's today's roster). **Starters on bye** (migration `20261021150000_live_bye`): a bye player never kicks off, so `live_lineups` also returns `bye` (his team has no game this week, while the week has games): the slot is flagged for everyone at once ("🔒 Starter on bye", counts toward the warning) but he's named only to his team and the commissioner until the **week's last kickoff** (until then his manager can still swap him out: no kickoff lock). While a bye slot is hidden, bench players on bye aren't listed either. Injury statuses come back the same way (`injury`, see Injuries below).
- **Injuries** (migration `20261021180000_injuries`, `src/league/injuries.ts`, decided 2026-10-21): **source nflverse**, both files keyed by GSIS ID (our player ID, no crosswalk): the NFL's official weekly **injury report** (`injuries_<season>.csv`: Out / Doubtful / Questionable, primary injury, practice status; per week, so past weeks keep their statuses) and **roster status** from `players.csv` (`status` + `ngs_status_short_description`: injured reserve "IR", PUP, Suspended, other reserve "Reserve"; current week only). Most serious wins (reserve lists > Out > Doubtful > Questionable). Chosen over ESPN's league-wide injuries feed (one 8.7 MB request, ESPN IDs needing the crosswalk); ESPN would add **game-day inactives**, which nflverse doesn't have (known gap). Written nightly by `scripts/sync-nfl.mts` (finalize workflow) via `public.replace_injuries(season, from_week, rows)` (service_role only): weeks from the current one are replaced in one transaction (a player dropped from the report is healthy again), earlier weeks upserted. The report's Friday designations land in the Saturday 09:17 UTC run (Thursday games: the Thursday run). Table `public.player_injuries` (season, week, player_id, status, injury, practice, source report|roster): public read. `live_lineups` returns `injury` for every slot, hidden ones too (a warning, not a name). **Page:** warning levels out (IR, PUP, Suspended, Reserve, Out), doubtful, questionable; cards and the matchup header show "⚠ 1 starter on bye · 2 out · 1 doubtful" (red) and "1 questionable" (gold), counting starters who haven't finished (a bye outranks an injury); players get tags (IR / PUP / SUSP / RES / OUT red, D orange, Q gold outline), a starter who's out has a red name, a hidden starter shows "🔒 Starter listed OUT", bench players get tags too, and the breakdown opens with "Injury report: Questionable (Hamstring) · Limited Participation in Practice". Tests: `injuries.test.ts` (statuses, precedence, current week, roster status only for the current week), "injury statuses" in `rls.test.ts` (public read, hidden starters flagged, atomic replace, only server jobs write), `live-page.test.ts` (warning counts and the card line, lineup statuses incl. bench). On 2026-10-21 week 7 had 121 IR, 8 PUP, 11 other reserve among fantasy positions; designations arrive with the week's reports.
- **Realtime:** the browser opens Supabase Realtime directly (Phoenix protocol over a WebSocket in `live.js`, no supabase-js; `wss://<ref>.supabase.co/realtime/v1/websocket?apikey=<publishable>&vsn=1.0.0`, signed-in users add their JWT) and subscribes to `postgres_changes` on **`score_weeks`** (`season=eq.<season>`; added to publication `supabase_realtime` by the migration). The live scorer upserts that one row per pass, so it's **one small message per pass per viewer** (~1,300 passes/week); on a message the page re-reads the week (score_weeks, nfl_games, matchups, `live_lineups`; on a detail page also roster, those players' `player_scores` and `score_events`). Reconnects with backoff; a 60 s poll only while games are on and the socket isn't joined. Why not subscribe to `player_scores`: ~1,000 row changes per pass x viewers would blow the free tier's 2M messages/month.
- **"updated Xs ago" and the stale notice:** from `score_weeks.updated_at`, ticking every second. "Live scoring delayed — showing the last good numbers." when a game is on (in progress, or kicked off < 4.5 h ago and not final) and the last pass is over 3 minutes old, or the scorer set `live_delayed`. Not shown once nflverse has the week.
- **2026 (MFL is official; TEMPORARY, remove with the other MFL code):** label "Unofficial — MFL is official for 2026." (`season < LEAGUE.lineupsFrom`). `src/live/mflLive.ts`: MFL's public `TYPE=liveScoring` export (no login) gives each franchise's starters and MFL's live points. Starters -> `lineup_slots` **refreshed until each player's kickoff**: a starter whose game has started keeps his slot; MFL starters already kicked off that weren't ours are ignored and reported; a team with no lineup yet takes MFL's as is. Runs from pg_cron **`b5-mfl-lineups`** (every minute; `private.mfl_lineups_tick()` acts every 15 min, or every minute in the 30 min before a kickoff, only for season 2026 and only while a game of the current week hasn't kicked off; Edge Function job `mfl_lineups`, same nonce auth) and from every live pass (replaces the old `weeklyResults` mirror). **Comparison:** our totals (our lineup x our points) vs MFL's live scoring, per team and starter, into `live_compare` (commissioner only; `diff_since` = when a difference first appeared). Commish card "Live scoring vs MFL" (match / differs for N min, per-player detail). MFL's live numbers can lag ours by minutes; a lasting difference is the one to check.
- **Free-tier budget:** Realtime: 1 message per live pass per open page (~1,300/week x viewers; 200 concurrent connections allowed). Egress per refresh: scoreboard ~15 KB uncompressed (6 matchups, ~16 games, ~108 lineup rows), detail adds ~2 teams' players with lines and the feed (~20–40 KB). Only refreshes on a Realtime message, or the 60 s fallback poll while games are on. `b5-mfl-lineups`: ~850 Edge Function calls/week in season (pre-game), well inside 500,000/month.
- **Tests:** `src/workers/live-page.test.ts` (game status transitions, done/playing/to go, card status, stale notice, 9 slots with hidden/empty, bench excluded from the total, feed order and big plays, breakdown sums, byes (own status, never Live on byes alone, BYE starters counted, hidden bye slots, bench held back), week links stay on Live, `#live/<week>/<team>` deep links and old-link redirects, selection (deep link > my team > first card), card HTML with the selected card), `src/live/mflLive.test.ts` (liveScoring parsing, kickoff locks, comparison), `liveRun.test.ts` (breakdown stored, nfl_games before player_scores, comparison written, `mfl_lineups` job), "Live page (public read)" in `rls.test.ts` (lineups revealed at kickoff, bye slots flagged and named after the week's last kickoff, scoring-play trigger, `live_compare` commissioner-only, `b5-mfl-lineups` schedule). ## Message board (built 2026-10-22)
- **Members only, enforced by the database:** every board table has RLS with `private.is_member()` (manages a team or is the commissioner); **anon has no grants at all** (permission denied), and a signed-in account that isn't on a team sees nothing and can't post. The page (`board.js`, `window.B5Board`; nav "Board" after Live, with an unread badge) shows signed-out visitors "Sign in to view the board" and non-members "The board is for league members". Routes `#board`, `#board/<threadId>` (`route.js`).
- **Tables** (migration `20261022120000_board`): `board_threads` (title ≤120, author, author_team, pinned, locked, `source_key` unique for bot posts and cross-posts, `last_activity_at`, `last_author_id`, `reply_count`, `edited_at`), `board_posts` (opener `is_opener` + replies; body ≤10,000 chars; `images` jsonb ≤4), `board_reactions` (👍 😂 🔥 💀 🗑️, PK post+user+emoji = one of each per person), `board_reads` (per member, per thread), `board_visits` (first visit), `board_settings` (B5 Bot toggles; members read, commissioner updates), `board_bot_keys` (server jobs only). RPCs: `board_new_thread(title, body, images, source_key)` (thread + first post in one transaction; `source_key` only for the commissioner) and `board_unread()` (badge count).
- **Guard triggers** (run as the caller): author, author_team (`private.my_team()`), timestamps and `is_bot` are set by the database (forgeries are overwritten); a post's thread, author and opener flag never change; `edited_at` is stamped only when the body/images/title really change (can't be forged or cleared); a locked thread takes no replies except the commissioner's; only the thread's author writes its first post; **rate limit 10 posts a minute per member** (`private.board_rate_limit`, "Slow down"); images must be `https://...` (no spaces, quotes or angle brackets, ≤1000 chars) or `storage:<uid>/<uuid>.<png|jpg|jpeg|gif|webp>`, at most 4. Policies: you edit only your own posts (the commissioner can't edit others' text; he deletes), you delete your own replies, your own thread only while it has no replies, and the opener only by deleting its thread; **the commissioner deletes anything, pins and locks**. Activity (`last_activity_at`, `reply_count`) is kept by a definer trigger. **Audit:** the commissioner deleting someone else's thread or post, pinning/unpinning and locking/unlocking go to `audit_log` (`board:board_threads:delete`, `board:board_posts:delete`, `board:threads:pin|unpin|lock|unlock`); posts removed with their thread are covered by the thread's entry.
- **Formatting and sanitizing (`board.js` `formatBody`):** text only. Everything is HTML-escaped first; then `**bold**`, `*italic*` (asterisks must hug the text), `[text](https://… or #route)` and bare `https://` links (`target=_blank rel="noopener noreferrer nofollow ugc"`; in-site `#` links stay in the tab), `@mentions` (team names and display names, one pass, longest first; mentions of you highlighted) and line breaks. No other markup survives; `javascript:`/`data:` links stay plain text. Tests: `src/workers/board-page.test.ts` (an attack list: script tags, event handlers, script URLs, attribute breakouts; only `a/strong/em/br/span` can appear).
- **Images:** up to 4 per post. Paste a direct https image/GIF link, or upload from the phone's camera roll / computer (`accept="image/*"`). Uploads go to the **private Storage bucket `board-images`** (created by the migration: `file_size_limit` 5 MB, `allowed_mime_types` PNG/JPEG/GIF/WebP, enforced by Supabase Storage); Storage policies: members upload only into their own folder (`<uid>/…`, image extensions), members read, the uploader or the commissioner deletes. The page checks type and size first (`checkUpload`; SVG and video refused), and **shrinks photos** to 1600 px JPEG ~85% in the browser (a 4 MB phone photo becomes ~300 KB; GIFs stay as they are, animated). Shown inline (max-width 100%, max-height 420 px) through **1-hour signed URLs** (one batch request per thread view), so images are as private as the board. Deleting a post (or thread) also deletes its uploads. The test database has a Storage stand-in (`src/db/testdb.ts`) so the bucket config and policies are tested.
- **Unread:** a thread is unread when someone else's activity is newer than your `board_reads` entry for it, or (never opened) newer than a week before your first visit (`board_visits`). Opening a thread marks it read. The nav badge (`board_unread()`, "9+" max) refreshes on every page change and live.
- **Realtime** (`realtime.js`, `window.B5Realtime`, shared with `live.js`): each signed-in member keeps one socket on every page, subscribed (with his JWT, so RLS applies) to `postgres_changes` on `board_threads`, `board_posts` and `board_reactions` (added to `supabase_realtime`). A change refreshes the badge and, on the board, the list or the open thread (debounced; drafts being typed and edits in progress are kept). Reconnects ask for a fresh session.
- **Commissioner** (on the thread: Pin/Unpin, Lock/Unlock, Delete thread, Delete on any post). **Commish card "Message board":** B5 Bot toggles (weekly recap, payout awards) and the home-page announcements (`league-data.js`) with "Cross-post to board" (thread authored by the commissioner, `source_key` `announcement:<date>:<slug>` so it can't post twice; HTML becomes board text with links kept, `htmlToText`), then "On the board".
- **B5 Bot** (`src/league/boardBot.ts`, `scripts/board-bot.mts`, nightly in `finalize.yml` after payouts; service_role, posts have no author and a gold "B5" avatar): **weekly recap** when a week is `final` in `score_weeks` (high score with its prize and ties split, guillotine chop, biggest blowout, closest game) and **payout awards** when they become `final` (weekly highs are left to the recap). ## Add/drop and waivers (built 2026-10-22; replicates MFL's B5 settings)
- **Every rule is a season setting** (`season_settings.waivers` jsonb, defaults merged by `private.waiver_settings(season)`): `live` (false for 2026: MFL is official), `rosterMax` 18, `rounds` 8, `dropLockHours` 24, `reverseDropMinutes` 30, `waiversStart` {isodow 1, "22:00"} (Monday 10 PM ET), `process` {isodow 3, "17:00"} (Wednesday 5 PM ET), `lockAfterLastKickoffHours` 4 (the week's last game "ends" 4 h after its kickoff), `preseasonOpenDays` 2, `closeAt` (2026: 2027-01-03 1:00 PM ET, MFL's value). - **Availability = `private.move_status(season, player, at)`** -> `rostered` / `closed` / `claims` (with `until` and a reason) / `fcfs`, in this order: closed before the first kickoff minus `preseasonOpenDays` and after `closeAt`; **locked** from his own NFL kickoff until the week's last kickoff + 4 h (claims only; can't be dropped either); **on waivers** from Monday 10 PM to Wednesday 5 PM ET (`private.waiver_window`, DST-safe through `America/New_York`; only once the season has kicked off, so preseason is FCFS); **dropped in the last 24 h** (claims only); otherwise free agent, first-come-first-served. - **Moves:** `public.roster_move(season, team, add, drop)` (FCFS add, add+drop, or drop only; owner or commissioner; refuses when not live, locked, on waivers, over 18 without a drop) writes `roster_entries` and a processed `transactions` row (`via` free_agent / commissioner, `created_by`). ## Scoring engine (built and verified)
- Code: `src/scoring/` (`rules.ts` = the B5 rule set, `engine.ts` = `scoreStatLine(position, statLine)`, `types.ts`). Pure TypeScript, provider-agnostic, returns a total plus a per-rule breakdown. Rules are data, so they're configurable.
- **`src/scoring/rules.ts` is the source of truth.** It was copied rule for rule from MFL's `TYPE=rules` export (2025 and 2026 rules are identical). The `scoring` block in `league-data.js` is only a display summary; keep it in sync.
- Tests: `npm test` (Node's built-in runner, TypeScript run natively by Node 24). `npm run typecheck` runs `tsc`. There are hand-calculated tests for every position and boundary, plus real games with MFL's official scores as the expected totals.
- **Verified against MFL's official scores** through the nflverse adapter: 2025 weeks 1–17 and 2026 weeks 1–5, **10,030/10,030 player and defense games matched exactly.**

Rules, as MFL actually scores them (not standard PPR):
- **TDs pay by length** (yards of the scoring play). Passing TD: 0–30 = 6, 31–50 = 8, 51–75 = 10, 76+ = 12. Rushing TD: 0–10 = 6, 11–20 = 7, 21–30 = 8, 31–50 = 10, 51+ = 12. Receiving TDs use the passing scale for QB/RB/WR and the rushing scale for TE. Needs **play-by-play with play distance**.
- **Receptions:** 0.5 for RB and WR, 1 for TE, **0 for QB**.
- **Total yards = passing + rushing + receiving** (MFL "yards from scrimmage"), tiered by position. The top tier **continues from the tier below**; it doesn't restart from zero. **Rechecked 2026-10-22** when a spec said passing yards never count: MFL's `TYPE=rules` export applies the QB yardage tiers to passing + rushing + receiving, and MFL's official 2026 QB scores only match with passing yards included (all 10,030 player games match as is; without passing yards nearly every QB is off). The engine was left unchanged; boundary tests in `engine.test.ts` ("total-yards tier boundaries": QB 199/200/249/250, RB 99/100/124/125, WR 99/100/125, TE 74/75/99/100, QB receptions 0, DEF 2-pt returns, OPPOPS only at 0 points):
  - QB: 50–99 = 1, 100–149 = 2, 150–199 = 3, then **5 at 200, +2 per full 50** (250 = 7, 300 = 9).
  - RB: 25–49 = 2, 50–74 = 4, 75–99 = 6, then 8 at 100, +2 per full 25.
  - WR: 25–49 = 1, 50–74 = 2, 75–99 = 4, then 6 at 100, +2 per full 25.
  - TE: 1–24 = 1, 25–49 = 2, 50–74 = 4, then 6 at 75, +2 per full 25.
  - Negative totals score 0.
- **Misc offense:** INT thrown −1. 2-pt pass, rush or catch 2. RB/WR/TE: punt, kick and INT return TDs and fumble-recovery TDs 6 each. QBs only get the fumble-recovery TDs.
- **Kicker:** FG 1–30 = 3, 31–59 = 0.1 × yards (3.1 at 31), 60+ = 10. Extra point 1. Any TD by the kicker 6. INT thrown −1.
- **Defense:** INT 2, fumble recovery 2 (defense or special teams), sack 1, safety 2, blocked FG or punt 1. Punt, kick, INT and fumble return TDs and blocked-kick TDs 6 each. Defensive 2-pt return 2. **Net** passing yards allowed (after sacks): 1–149 = 6, 150–174 = 3, 175–199 = 1. Rushing yards allowed 0–99 = 6. No offensive (pass/rush) TDs allowed 8. Opponent held scoreless 2 (MFL code `OPPOPS`, confirmed by 2025 shutouts).
- **Quirks kept on purpose** because MFL does them: 0 or negative net passing yards allowed scores 0, not 6. Negative rushing yards allowed scores 0. The engine refuses to score a defense when the allowed-stats are missing, since a missing value read as 0 would award shutout points.
- Stat corrections from the feed must re-score past weeks.

## Stats ingest (`src/ingest/`)
Decision (final, 2026-10-14):
- **Live scoring: ESPN's public JSON endpoints** (unofficial and undocumented; they can change or break without notice). Use the scoreboard to find in-progress games, and the per-game summary / play-by-play for player stats and every scoring play with its yardage.
- **Final scoring: nflverse** (nflfastR play-by-play + player stats) is the **system of record**. It updates nightly in season.

Build rules:
1. Two adapter interfaces: `LiveStatsSource` (ESPN) and `FinalStatsSource` (nflverse). Both produce the provider-neutral model in `types.ts` (`GameData`). The scoring engine never sees raw provider JSON, so either source can be swapped.
2. Our engine computes all fantasy points from play-level data (TDs pay by length). **Never use a provider's fantasy points.**
3. Player IDs: ESPN and nflverse IDs differ. Build a crosswalk table (nflverse's ID map includes ESPN IDs). **Flag unmatched players for commissioner review; never guess.**
4. ESPN polling: only during live game windows, every ~30–60 s, with backoff and caching. If ESPN errors or changes shape, show "live scoring delayed" and keep the last good numbers. **Never crash matchups.**
5. Finalization: a nightly job pulls nflverse, rescores the week and overwrites live numbers. Log every live-vs-final difference for the commissioner. A week is marked "final" only after the commissioner confirms, or by auto-finalize Tuesday night (configurable). Re-run on later nflverse updates to pick up NFL stat corrections until the week is locked.
6. The commissioner can override any player's stat line or score, with an audit log.
7. Tests: hand-calculated scoring-engine lines including a 52-yd TD reception, a 12-yd TE TD, a 47-yd FG, QB 210 total yards, and a defense allowing 160 pass yds.

What exists:
- `statlines.ts` is the ONLY place that turns `GameData` into engine `StatLine`s and decides which TD credits what (e.g. kick return TD -> returner + his team's DEF; own-fumble recovery TD -> player only). Team codes normalize through `teams.ts` (unknown codes throw). `http.ts` = request spacing, retry/backoff, disk cache.
- **nflverse** (`nflverse.ts`): verified 100% vs MFL's official scores (10,030/10,030). Lessons baked in: nflverse's `return_touchdown` misses blocked-kick TDs, kickoff recoveries and INT-then-fumble TDs, so non-offensive TDs are classified by scoring team vs `posteam`. On kickoffs `posteam` is the RECEIVING team. Fumble recoveries are counted per fumble slot, with a fallback for chains longer than nflverse's two slots (not touchbacks). Net passing yards = passing yards + sack yards.
- **ESPN** (`espn.ts`, `espnLiveSource()` = `LiveStatsSource`): verified against nflverse: **2026 weeks 1–5, 1,865/1,865 player and defense games scored identically; full 2025 season (weeks 1–17), 6,040/6,041.** The one 2025 miss is a player with no crosswalk entry, correctly flagged for review. (`scripts/verify-espn.mts <season> <weeks...>`). Every rule below came from a real mismatch. How it works and why:
  - Per game: the site **summary** (`site.api.espn.com/apis/site/v2/sports/football/nfl/summary?event=<id>`) gives header/status, box score (player yards, receptions, INTs thrown, XPs) and team stats (`netPassingYards`, `rushingYards`, `sacksYardsLost` "3-22", `interceptions`). The **core plays** feed (`sports.core.api.espn.com/v2/sports/football/leagues/nfl/events/<id>/competitions/<id>/plays?limit=1000`) gives every play with **participants by ESPN athlete ID** (passer, receiver, rusher, scorer, kicker, punter, returner, recoverer, patPasser, patScorer, ...), `statYardage`, `scoreValue`, `pointAfterAttempt`. Scoreboard: `.../scoreboard?dates=<season>&seasontype=2&week=<w>`.
  - **Scoring is driven by the summary's `scoringPlays`** (reliable scoring team and running score), joined to core plays by `id` for participants and yardage. The core plays' running score can lag a play behind; don't use it.
  - TD length and FG distance = `statYardage`. Two-point conversions are on the TD play: `pointAfterAttempt` "Two Point Pass/Rush", players `patPasser` / `patScorer`. **`value` is what the try was worth, NOT success** (failed tries can show 2). A try succeeded only if "ATTEMPT SUCCEEDS" appears in the offense's part of the text (before "DEFENSIVE TWO-POINT") or the summary entry is worth 8. Defensive 2-pt returns = the other team scored 2 on the same summary entry. XPs come from the box score.
  - **Participants beat labels:** ESPN labelled a bobbled-but-caught TD pass "Fumble Recovery (Own)". Passer present + receiver = scorer means a passing TD. Defensive TD kinds come from scoring team vs offense, returner = scorer, and "BLOCKED" in text. **A listed scorer must be on the scoring team** (ESPN has named the blocked kicker as the scorer of a blocked-FG return). If the scorer role is missing or wrong, use the player the summary text names, only from that play's participants on the scoring team (e.g. "George Holani Recovered Kickoff in End Zone" lists him as "other").
  - Opponent fumble recoveries: NFL text capitalizes "RECOVERED by TEAM-" only for opponent recoveries (lowercase = own). ESPN sometimes replaces the text with a short summary. Only then (no official "recovered by TEAM-" / "and recovers at" wording) fall back: labels "(Opponent)" / "Opp Fumble" are trusted, with the recoverer's team (their "fumbler" role is often the pass rusher). A generic "Fumble Return" label counts only if fumbler and recoverer are on different teams. Official text beats labels: an own-fumble TD was labelled "Fumble Return Touchdown", and a sack safety listed the rusher as "fumbler". Skip "NULLIFIED" / "No Play" plays. After "REVERSED." only the trailing text counts.
  - On kicks ESPN's play `team` is the receiving team. Blocked FG/punt: on a blocked kick returned for a TD the blocker is the scoring team (the listed "kicker" can be the scoring team's PAT kicker); otherwise the opponent of the punter's (punts) or kicker's (FGs) box-score team. Short summaries ("Blocked Kick Recovered by ...") count by play type, but official text wins: ESPN labelled a missed, returned FG "Blocked Field Goal". Blocked PATs aren't blocked FGs.
  - **Never throws:** scoreboard or game failures, and shape changes, return the last good data with `delayed: true` plus `errors`. Live games are always re-fetched; finished games are disk-cached. Scheduled games make no detail requests. The polling scheduler (live windows only, 30–60 s) is not built yet.
- **Crosswalk** (`crosswalk.ts`): ESPN athlete ID -> nflverse GSIS ID (our canonical player ID) from nflverse `players.csv` (`espn_id`), cached 24 h. ESPN IDs claimed by two players are treated as unmatched. `toCanonical(game, crosswalk)` rewrites refs; unmatched players keep their ESPN identity, are returned as `UnmatchedPlayer` for the commissioner's review queue, and are never name-matched. All 524 fantasy-relevant ESPN athletes in 2026 weeks 1–5 mapped. In 2025 one (Chris Manhertz, ESPN 2531358) had no entry and was flagged, as designed.
- Earlier spike (`scripts/spike-espn-vs-nflverse.mts`): ESPN and nflverse agree on all 411 TDs in 2026 weeks 1–5 (scorer and yardage).
- `scripts/bakeoff.mts <provider> <season> <weeks...>` compares a source's scores to MFL's official scores (2026 only). Caches live in `.cache/`, MFL answer keys in `.bakeoff/` (gitignored).

## Live scoring and finalization (`src/league/`)
Build rules 4, 5 and 6 are implemented.
- **Scores** (`scores.ts`): `scoreWeek()` turns a week's `GameData` (canonical player refs) into a `WeekSnapshot`: every fantasy player (by nflverse position via the crosswalk) and team defense, with stat line and points. Players are keyed `nflverse:<gsis>`, games `AWAY@HOME` (ESPN and nflverse game IDs differ). Unmatched/non-fantasy players are never scored. `mergeLive()` carries games a delayed snapshot lacks from the previous one (last good numbers survive restarts). `diffSnapshots()` lists point and stat changes.
- **Store** (`store.ts`): `ScoreStore` interface; `jsonFileStore(dir)` implements it until Postgres exists (swap the implementation, keep the interface). `live/<s>-w<w>.json` is written only by the poller; `weeks/<s>-w<w>.json` (status, final snapshot, diff log) only by the finalizer and commissioner tools; plus `review.json` (unmatched players) and `audit.jsonl`. Writes are atomic (temp file + rename).
- **Live poller** (`livePoller.ts`, `scripts/live-poller.mts`): current week from ESPN's default scoreboard. It polls only in live windows (a game in progress, or a kickoff within 10 min, including late starts), every 30–60 s with jitter. Errors back off exponentially (cap 5 min). Otherwise it sleeps until 10 min before the next kickoff, at most 6 h. It never throws, never writes over a final week, and queues unmatched players for review.
- **Finalizer** (`finalizer.ts`, `scripts/finalize.mts`, run nightly): rescores every unlocked week from nflverse and overwrites live. **Missing games are checked against the full NFL schedule** (`deps.schedule`, nflverse `games.csv`; fixed 2026-10-20 after week 6 was marked pending_review while Monday night was unplayed, because only live-polled games used to count). A week with any scheduled game missing from nflverse stays **`live`** (live scoring continues, `weekScores` shows final numbers plus live numbers for the unfinished games, `shadow.mts` leaves it alone); it moves to `pending_review` only when complete. Logged diffs: `live_vs_final` for games new to nflverse (vs the live numbers; a note if no live numbers were recorded), and `correction` for games already finalized (NFL stat corrections). Week status: `live` -> `pending_review` (nflverse in) -> `final` (locked). Locking is by commissioner confirm, or auto-finalize (default Tue 11 PM ET after the week's last game, from live kickoffs or nflverse game dates; `AUTO_FINALIZE=off` or `<weekday>@<hour>`). Never while a scheduled game is missing from nflverse. Confirm refuses while games are missing unless forced. Reopen needs a reason. Both are audited, and auto-finalize is audited as `system`.
- **Overrides** (`overrides.ts`, rule 6): the commissioner can override any player's or defense's stat line (`stats`: replaces only the given fields, `null` removes one; points recomputed by the engine) or pin the score (`points`, beats a stats override; latest wins). Overrides are stored per week in `overrides/<s>-w<w>.json`, separate from live and final, and **applied at read time**, so nightly re-runs and stat corrections never erase them. Stored final numbers stay raw. Removal deactivates (history kept). Add and remove require a reason and are audited, with target, values and week status. They work on locked weeks too (the commissioner can edit anything). An override can credit a player the source lacks (e.g. one flagged as unmatched), but never a non-fantasy position. The commissioner (an IT director, deploying to a new domain they're registering) chose:
- **Stack:** one Node + TypeScript codebase. It runs the web app, the API and a background worker (stats ingest, scoring, waivers, lineup reminders, other scheduled jobs). Data is in **Postgres (Supabase)**. Live scores are pushed to browsers (server-sent events or WebSockets). Logins are magic-link email (no passwords), with a commissioner role.
- **Hosting:** superseded 2026-10-15: GitHub Pages front end + a backend still to be chosen (see Hosting and deployment above). Originally a managed host with managed Postgres (Render or Fly.io class).
- **Front end:** a light framework with a build step (e.g. Preact or Svelte) is acceptable for the draft board, live scoreboard and phone lineup screens. Keep the current look.
- **Stats sources (final decision, 2026-10-14; replaces the BALLDONTLIE / MySportsFeeds bake-off, whose adapters were deleted):** ESPN for live, nflverse for final. See Stats ingest above.
- **Notifications:** email (Amazon SES or Postmark/Resend, with SPF/DKIM/DMARC on the new domain) plus web push. SMS is deferred unless push falls short.
- **Provider-agnostic core:** providers feed a normalized stat line into the scoring engine. The engine never talks to a provider directly.

## Conventions
- **Look:** keep the current black and Steelers-gold theme (CSS variables at the top of `style.css`: `--ink` / `--ink-deep` black, `--gold` #FFB612, `--chalk` off-white), Oswald headings + Inter body, and the scoreboard countdown on the home page.
- The site name is "Bridgeville 5 Fantasy Site" (short: "B5").
- Escape all data fields with `esc()` in `app.js`. The only exception is announcement `body`, which is commissioner-authored HTML on purpose.
- Team names render only through TeamLink (`B5Team.link`, see "Team profiles, TeamLink, DMs and trades"); `teamlink.test.ts` fails otherwise.
- Must work at phone width (390px). Nav collapses to a menu toggle below 760px.
- Times are US Eastern.
- Keep dependencies minimal and justified.
- **Cache busting:** every script and `style.css` in `index.html` carries `?v=<version>`. Bump it when the file changes, or browsers keep the old copy for up to 10 minutes (GitHub Pages caching) and new pages break against old scripts.
